# Stored markup compatibility

SharpMUSH never rewrites or upgrades stored markup on its own.

Attribute aggregates retain their original UTF-8 JSON serialization with the library's inspection status, display projection and `CanRewrite` decision. Ordinary display reads defer the expensive codec rewrite inspection until a safety decision requests it. Existing Mediator queries carry that provenance; writes use the attribute store and the normal invalidating command. Copy, move, clone, snapshot capture and unsafe snapshot restore preserve original serialization, including structurally valid Damaged values. Malformed/non-object JSON is excluded rather than repaired. Raw writes construct prepared bytes directly and never invoke the display value serializer, including when a codec can read but cannot write. Attribute permission, creator and value restrictions still apply. If a value restriction would normalize the text of a stored copy, the copy is refused rather than silently altering its serialization.

`@edit` preflights all matches before evaluating replacement expressions or writing anything. Unsupported or damaged values refuse the entire operation with one message. Complete and opaque values follow the library's `CanRewrite` decision. An explicit attribute replacement remains available. `edit()` is a string operation: evaluated text has no reliable persistence provenance and is not treated as an attribute write.

Malformed JSON attribute rows are skipped independently with a diagnostic naming the row. Exact authorization reads retain valid flags and owner metadata with an explicit unreadable-value marker; display services refuse that value. Unreadable access metadata fails closed with a distinct data error mapped to one service refusal. Display/copy enumeration continues to unrelated neighbours and omits unreadable subtrees. Command/listen discovery uses a separate metadata-preserving stream: unusable bodies still retain their real flags and shadowing names; unparseable metadata explicitly masks its name and subtree across parents. Unreadable discovery bodies are never compiled or executed. Lazy metadata readers remain lazy; display-only/index projections can suppress an unreadable body, but never turn that fallback into a stored-value copy. Numeric semaphore changes also refuse unsafe stored values, including numeric future-version fallback text; repairs retain their existing barriers rather than overwrite incompatible data.

Scene edits inspect the current stored content before changing the history pointer, writing a new version or truncating redo history. An unsafe current value returns an explicit error. Original markup remains in the history record. Legacy bare-text submissions remain supported, including text beginning with braces. A malformed stored markup projection cannot be edited through a degraded display fallback. The plugin `ISceneService.EditPoseAsync` result is now `FoundResult<ScenePose>` (pose, not found, or error); plugin callers must handle the error case. Existing missing-pose behavior is unchanged.

## Reader-first deployment and rollback

Ship readers to every consumer first: server, rendering worker, plugins and portal. Only after all deployed consumers understand a future wire format may a writer start emitting it. A writer introducing a new format must first stamp the world's minimum reader version; older servers must refuse to open that world at startup with one clear diagnostic. There is no new format in this release, so no version stamp is introduced now.

Before enabling such a writer, take a verified world backup and document the reader/writer versions. After enabling it, rollback requires a compatible reader or restoring the pre-upgrade backup; preserving opaque/future bytes is not permission for an older server to rewrite them. Do not run a bulk deserialize/serialize migration to downgrade unknown data. Restore a copy of the backup and verify it before switching the live world.
