# Rhost native backup export bridge

The operator requested a PR for #1963, whose requirements explicitly permit a tested upstream export bridge. This PR implements that bounded route: a standalone operator-run .NET tool exports a stopped, consistent Rhost backup into the existing SharpMUSH flatfile/mail import format. It does not register a runtime database provider or claim production import staging is implemented. #1963 stays open for the remaining integration/completeness work.

## Contract

- Explicit `legacy-qdbm` or `mdbx`, pinned Rhost revision `bfd2894c7239d02b8bec15c36939706be371715c`, default upstream caching layouts, Linux x64 little-endian ABI. Historical GDBM and nondefault caching require separate profiles and are refused.
- Legacy input: selected structural checkpoint plus `<base>.db`, `.dir`, `.pag`. MDBX input: selected structural checkpoint plus `<base>.mdbx`. A stopped coherent backup is an operator prerequisite; hashes do not establish cross-file consistency.
- The selected checkpoint must be native v7 with external attributes. Backend/profile/file-set contradictions, missing files, symlinks, path overlaps, preexisting output and incompatible exporter/profile hashes fail before process launch.
- The trusted backend-matching upstream `dbconvert` is supplied by the operator with a build profile generated by the committed fixture/build recipe. The profile binds revision, backend, ABI and exporter SHA256. This checks identity, not executable safety; arbitrary uploaded executables are never executed by the server.
- Inventory and hash source files, copy into a new private writable directory under the output parent, verify copied hashes, run only `dbconvert <private-base> x` with checkpoint bytes on stdin. No shell and no repair/check flags. The exporter may write only to its private copy by the supplied paths; this is not an OS sandbox guarantee for the trusted binary.
- Pump input/output/error concurrently with cancellation, timeout and byte limits. Kill and await the process on failure. Require exit zero, bounded empty/recognized-success stderr policy, a complete v7 flatfile with external-attributes flag cleared, strict parse/readback and valid basic object/attribute relationships. Translate in memory for unmappable-data diagnostics.
- Optional `wmail/unload` mail/folder text companions are parsed strictly and copied. Native mail stores are not decoded by dbconvert: detect/report declared omission and require portable companions when native mail files are present. Existing flatfile importer behavior is retained.
- Rehash originals after export and before publication. Write `world.flat`, supplied portable companions and provenance JSON into an incoming output directory, then atomically rename to a previously absent output. Cancellation/failure leaves no published output and does not touch a SharpMUSH world.
- Preserve a precise limitation: exit zero and parse success cannot independently prove every external attribute existed/read successfully. Real backend fixtures, required store files, profile identity, diagnostics and corruption tests establish the supported cases; no universal completeness claim. Future healthy-source semantic inventories/strict upstream verification remain tracked by #1963.

## Implementation choices

Use the repository's .NET11 SDK and `SharpMUSH.Library` Rhost readers/translator. Keep production Server/Lightning dependencies out of the tool. Public orchestration is testable from the existing test assembly. The committed recipe builds both actual upstream backends using bundled libraries and records its one standalone QDBM missing-include build repair; original upstream checkout stays unchanged.

Correct the migration guide's existing staging claim: the production converter currently writes its configured world directly. Document rehearsal on a disposable SharpMUSH world and file a dedicated staging follow-up instead of attempting a cross-cutting runtime/container promotion refactor in this export-tool PR.

## Evidence required

Real native fixtures from the same canonical world, backend exports semantically equal to the seed and to each other through SharpMUSH's reader, equivalent actual imported worlds, source hashes unchanged. Test missing/mixed files, wrong profile/backend/hash/version, corrupt/truncated payloads, malformed mail, process error/timeout/flood/cancellation, output collision and symlink/overlap refusal. Tests may use deterministic process doubles for failures; real-backend integration must use the actual verified binaries/recipe and clearly state when unavailable.
