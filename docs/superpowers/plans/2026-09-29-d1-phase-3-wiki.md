# D1 Phase 3 — Wiki Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle the wiki home (`/wiki`) and the wiki page (`/wiki/{ns}/{category}/{slug}`) to boards 21–24 with the Phase 0 kit, add the page sidebar, the `wiki-index` right-sidebar zone, the data README §7.5 asks for (editor name, page image, category cover), mentions and redlink colours, and a category listing and recent-changes route the sidebar links to.

**Architecture:** The server maps two more facts onto `WikiPageDto` (`LastEditedBy`, `Image`, the latter extracted from the Markdown by a shared `WikiImages` helper), and the client's `WikiArticle`/`WikiPageSummary` carry them. A `WikiLayout` hosts a `WikiSidebar` beside the wiki pages the way `ConfigLayout` hosts `ConfigSidebar` (Phase 1 moves both into the shell slot). `WikiIndexWidget` becomes the board-21 hero + category cards; `WikiIndex.razor` composes MainContent and a new `RightSidebar` zone (RecentWikiActivity, ActiveScene) side by side. `WikiDisplay` gains the glass banner, mentions, the 640px body card and a page aside (TOC + locales, Mentioned, More in category), all gated on `!Embedded`. Two small pages are added: `/wiki/category/{category}` and `/wiki/recent`.

**Tech Stack:** Blazor WASM, MudBlazor 9 (icons), the kit, bUnit + TUnit, ASP.NET Core controllers, xUnit-free TUnit controller tests.

**Spec:** `docs/design/d1/README.md` §3, §4.3, §4.8, §6.1, §6.2, §7.5, §9; boards 21–24; board sources `App-Wiki-Index.dc.html`, `App-Wiki.dc.html`.

## Global Constraints

- Everything in Phase 2's Global Constraints (shell owns `@media`; page tiers only; no `!important`; no `position: fixed` in scoped CSS; `::deep` anchoring; copy through resx; existing policies and routes kept: `wiki.read`, `wiki.edit`, `wiki.create`; `/wiki`, `/wiki/{ns}/{category}/{slug}`, `/history`, `/edit`, `/diff`; `/character/` links keep working).
- The biography on profiles (`WikiBodyWidget` → `WikiView Embedded=true` → `WikiDisplay`) must not gain a banner, sidebar or aside: gate on `!Embedded`; the home page on `/` stays a hero with no chrome (`WikiDisplayHomeChromeTests`).
- Wiki links change to `--accent`; redlinks to `--link-missing` with the dashed underline (README §4.8).
- Mentions: `/character/{Name}` links in wiki HTML render as `.mention` (colour unknown here → faint underline; §7.5's colour arrives with the profile-handler `color` field later).
- Player-facing keys (`Wk`, `Nav`, `Wid` prefixes) need all 16 resx files via `tools/i18n/add_keys.py`; the wiki hero copy moves into resx (README §6.1).
- Rulings (ledger them): the page image is the first Markdown image in the body (README §6.2 says to remove the in-body copy when the banner shows it, which is what that rule implies); a category cover is the first of its pages that has an image; `LastEditedBy` resolves `LastEditorDbref` to a name on the server; `WikiLayout` hosts the sidebar until Phase 1; "Recent changes" is a new route because nothing lists it today.

## Review Focus

1. A page whose first image is the only content still renders a body (the banner shows it, the body shows the rest, never an empty card with a duplicated image) (Task 5).
2. A page with no image renders the plain header and no `.kit-banner` (Task 5).
3. A biography embedded on a profile has no banner, sidebar, aside or Back link (Task 5, existing chrome tests).
4. `?q=` on `/wiki` pre-fills and applies the search (Task 4).
5. `/wiki/category/{category}` for a category with no pages shows the empty state, not a crash; the category name is the label, not a path segment (Task 4).
