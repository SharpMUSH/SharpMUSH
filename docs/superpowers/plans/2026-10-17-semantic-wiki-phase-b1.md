Reject an oversized subject, never silently enlarge a batch.
- Native read batch: at most 128 records or 128 KiB; cancellation every operation (stronger than every 32 steps). One caller-owned budget spans all batch/point reads: at most 8,192 logical native probes and 2 MiB charged bytes, with 4 MiB managed working-buffer accounting. These are bounds, not native-I/O preemption guarantees. 5 ms reader/writer duration is recorded, never claimed guaranteed.

Signed integers use sign-bit transformation plus big-endian bytes. Incarnation identity is not a title/slug; tombstoned IDs cannot be resurrected.
- Full-sync remains enabled for comparisons. Cancellation/timeout after submission does not prove abort; observe actual completion and use durable mutation IDs/status. No process test hooks or fault switches added to production classes. Native destructive fault experiments run only in a child process with a disposable database.

## Review Focus

1. Huge native values, failed point probes, and out-of-range boundary keys must not allocate uncharged copies or convert budget exhaustion into empty success (Task 1).
2. A real cursor failure must propagate with its native code, including failures during iteration; NotFound alone means end. A pure status-helper unit test is insufficient proof (Task 2).
3. Replacements at catalog capacity, metadata-only edits and zero-fact targets must atomically maintain all state without incoming-degree work or class-ID reuse (Task 4).
4. Late cancellation, map-full and ambiguous mutation retry must preserve one durable all-or-none result; observing a canceled caller is not observing a rollback (Task 5).
5. Full-corpus serialization must preserve every typed value/provenance/identity, including signed bounds, and prove index symmetry after reopen rather than relying on small fixtures (Tasks 3 and 6).

## Task 1: Byte-checked synchronous reads

**Interfaces (Library namespace):**
- `IBoundedReadTx.ReadValue(TableDef table, ReadOnlySpan<byte> key, NativeReadBudget budget) : Found<NativeReadValue>`. `NativeReadValue` is an IDisposable owner exposing its copied byte array until disposal; a missing result transfers no reservation.
- `IBoundedReadTx.ReadRange(TableDef table, ReadOnlySpan<byte> prefix, ReadOnlySpan<byte> inclusiveStart, ReadOnlySpan<byte> exclusiveEnd, ReadOnlySpan<byte> afterKey, NativeReadBudget budget) : NativeReadBatch`.
- `NativeReadEntry(byte[] Key, byte[] Value)`; `NativeReadBatch` is an IDisposable owner exposing `ImmutableArray<NativeReadEntry> Entries` and `bool Exhausted`. Empty end/after spans mean no explicit end/resume. Prefix and interval both apply; afterKey is strict. Only nonduplicate tables are supported; reject duplicate tables before native access. `Exhausted=false` means another read may be required, never a public has-more claim. Resume from last returned key.
- `NativeReadBudget(int maxProbes, long maxBytes, long maxWorkingBytes, CancellationToken cancellationToken)` exposes read-only consumed counters and `ChargeProbe()` / `ChargeBytes(long bytes)` / `ReserveWorking(long bytes) : NativeReadReservation`. Invalid limits reject immediately; checked arithmetic; methods throw `NativeReadLimitException` naming internal dimension. Each ReadRange has a fresh local 128-record/128-KiB allowance but consumes the shared object. Point reads share these hard single-record limits. Preparation must explicitly reject any encoded page/fact/summary/status value that cannot be read back under the single-record limit (key plus value bytes); the 256KiB total delta limit does not override this read limit. Budget isn't thread-safe and cannot be shared concurrently. NativeReadReservation is an IDisposable owner; ReserveAdditional(long bytes) reserves before allocation. Result owners transfer an internal per-call reservation on success. On failure/miss release only this call's outstanding working reservations; cumulative probe/byte charges remain. Repeated Dispose releases once. No public arbitrary ReleaseWorking(long) API. Arrays are borrowed until their owner is disposed and must be dropped then; ownership does not extend any native transaction lifetime.

Pinned native-length contract: LightningDB 0.23.1 MDBValue has only an internal readonly nint size field; AsSpan narrows unchecked and raw CopyTo ignores destination capacity. Use one private managed UnsafeAccessor to that exact field, read it by value, and check nonnegative/int-range/record bounds before any AsSpan or allocation. Do not access native pointer fields, guess offsets, reinterpret layout, or use unchecked CopyTo/CopyToNewArray. Use the checked span's CopyTo after reserving exact destination allocation. Test this binding against real native zero/small/multi-MiB values; missing/incompatible field access fails closed with no unchecked fallback. Record this explicit pinned-package implementation coupling and require review on every LightningDB upgrade. No external fork/package/PR is authorized or needed for the prototype bridge.

TableDef identity is name-only, so caller flags are not authoritative. Read actual persisted flags via handle.GetFlags(openTransaction) for every handle opened/reopened; requested TableDef flags can differ from an existing named DB. Publish canonical name-indexed entries (definition, handle, actual flags) and the ordinary handle map as ONE immutable-by-convention snapshot through one volatile reference, created only at Open/OpenTable and emptied at Close. Each Tx captures one snapshot once; never swap flags/handles independently or mutate a published dictionary. OpenTable runs serialized writer work while ordinary readers coexist, so exclusive lifecycle gating must not be assumed. Validate that metadata before native access; do not build/copy/scan the whole table catalogue per bounded read. Test fabricated same-name false-duplicate aliases, dynamic opens, concurrent open/read snapshot consistency, and fresh-store/native-environment reopen of a persisted duplicate table requested with duplicates:false. Actual separate-process verification remains in Task 5. Unknown or native retrieval errors fail closed. This is native handle metadata, not game-state caching.

Accounting contract: charge a logical seek/get/advance before calling native code, including misses and resume skips; GetCurrent retrieval is counted separately if invoked separately. Inspect native lengths before making spans/copies, charge inspected key/value bytes before decoding/copy, reserve copied arrays plus batch-entry/list overhead before allocation. A native record encountered twice costs twice. Check prefix/end against mapped spans before value copying; boundary key inspection still costs its probe and key bytes. Reject a single oversized record explicitly. Reaching 128 records returns a nonexhausted batch without an extra probe; a next individually valid row that would exceed the local byte cap returns the populated batch nonexhausted before copying that row. Charge the inspected probe/key and charge its inspection again on resume; the next native read starts after the last returned key. A single row larger than key+value cap, or shared hard-budget exhaustion, throws and returns no partial result. Shared budgets and local batching are distinct. Native arrays never escape; copied arrays remain owned/accounted until the result owner is disposed. Document conservative headers/alignment, entry/owner objects, builders and final immutable-array overlap. Input keys and decoded models require caller-owned accounting scopes too; decoded results are borrowed until that scope is disposed. Exception unwinding must not release reservations owned by earlier successful calls.

## Task 3: Typed storage encoding and bounded preparation

**Interfaces (tool namespace `.Native`):**
- `NativeKeys.EncodeInteger(long value) : byte[]`; `DecodeInteger(ReadOnlySpan<byte> encoded) : long`. Exactly eight bytes: `(unchecked((ulong)value) ^ 0x8000000000000000UL)` big-endian; wrong lengths reject.
- `NativePagePreparation.Prepare(SemanticSchema schema, PageSnapshot page, IEnumerable<SemanticFact> facts, long expectedStateVersion, Guid mutationId, bool deleted, CancellationToken ct) : NativePreparationResult`.
- `NativePreparationResult` union of `PreparedNativePage` / `ValidationFailure`. `PreparedNativePage` has an internal constructor and immutable validated Page, Facts, ExpectedStateVersion, MutationId, Deleted, RequestDigest; consumers cannot mutate arrays after validation. An internal immutable `SchemaIdentityDigest` is lowercase SHA256 of exact encoded schema identity; Task 4 compares it with the store schema before any write, including when versions match. Do not trust arbitrary CanonicalFactSet construction. Digest every effect-bearing input (schema identity, page fields/source stamp, canonical facts/provenance, expected state version and deletion); status key already identifies mutation ID. Same-ID retry with any changed effect-bearing input fails.
- `NativeCodec.EncodePage(PageSnapshot page) : byte[]`, `DecodePage(ReadOnlySpan<byte> data) : PageSnapshot`, `EncodeFacts(CanonicalFactSet facts) : byte[]`, `DecodeFacts(ReadOnlySpan<byte> data) : CanonicalFactSet`. Use explicit tagged typed scalar encoding, not default JSON serialization of compiler union internals. Preserve complete provenance and all PageSnapshot fields. Stored fixture page keeps original source snapshot stamp; durable native versions are separate.

Frozen scalar tags: PageRef=1, Integer=2, Boolean=3, Keyword=4 (byte). Frozen registry kinds: Page=1, Property=2, Keyword=3, Collection=4, Class=5 (byte). NativeModels also declares the plan’s NativeCommitResult cases so receipt types do not depend on later uncompiled stubs.

Keys use nonduplicate tables, numeric collection/property/keyword/page/class IDs and type tag; signed values inline, PageRef points to stable numeric registry IDs, final subject ID breaks ties. All numeric IDs are positive fixed-width unsigned 64-bit big-endian and checked before allocation. Page/summary/fact-bundle key is subject ID (8 bytes). Own-forward key is subject(8)+property(8)+type(1)+value(8). Reverse/equality/range posting key is collection(8)+class(8)+property(8)+type(1)+value(8)+subject(8). Type tags are explicit format-versioned values, and all typed values use eight bytes: signed integer encoding, positive PageRef/keyword numeric ID, or zero/one Boolean encoding. Registry lookup keys are type(1)+SHA256(32); registry reverse keys are type(1)+ID(8). Keep raw fact/provenance lossless in the separate fact bundle. Freeze/document this layout in Task 3 before Task 4 consumers start. Registry values retain exact external strings; lookup keys are SHA256 of typed external identity, with exact stored-value comparison (collision is an explicit error, never aliasing). IDs never reused. Schema registry is initialized once in a bounded job and immutable for B1; verify exact schema identity when reopening before any mutation. Property removal/schema migration are later work. During Apply, plan identity-only registry rows for the subject and distinct referenced PageRefs, whether or not their pages exist yet. An identity-only reservation has no page state and CAS version 0; later page creation reuses that numeric ID. A tombstone has durable page state, cannot be resurrected under the old PageRef, and a new incarnation uses a new external/numeric ID. This supports subject-before-target import without asserting target visibility/liveness. Include all registry/counter allocation in the bounded delta before writes; failed CAS/capacity cannot allocate IDs.

Apply returns a provisional result; CommitAsync exposes durable success only after WriteAsync completes its actual parent commit. All normal conflict/capacity returns happen **before any write**. After writes, any failure throws to abort. All canonical/summary/page/forward/reverse/state/affected old+new partition version/commit-sequence/status changes are in this job. Remove postings by exact keys reconstructed from bounded old facts, never DeletePrefix or incoming scans. Metadata-only and zero-fact pages still receive durable summary/state updates. Deleted pages become tombstones, clear own facts/postings, and preserve original incarnation; later new page uses a different ID.

In B1 these structural IDs are exact external strings inside the bounded canonical descriptor (at most 8KiB), not native keys; hash the descriptor for registry lookup and compare the exact retained descriptor. Native posting keys use the numeric class ID. No additional namespace/category/rule numeric registry kinds are implied; B2 must reconcile actual persisted wiki identities during integration. Check net refcounts/count/byte quota in the same writer job; replacing the last member may free a slot for its new class atomically. Existing class reuse doesn't increase count. Catalog capacity uses durable counters plus point lookups, not a full catalog scan each edit. Global policy/requirements versions in B1 are fixture constants, explicitly not trusted live auth epochs.
