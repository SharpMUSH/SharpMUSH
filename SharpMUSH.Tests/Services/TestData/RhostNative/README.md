# RhostMUSH native database fixtures

Generated offline from RhostMUSH/trunk revision bfd2894c7239d02b8bec15c36939706be371715c on Linux x86_64. No game server or production database was opened. No system packages were installed.

`seed.flat` derives from SharpMUSH.Tests/Services/TestData/rhost-sample.flat. Visible SOH metadata becomes actual byte 0x01; visible newline text becomes actual embedded CRLF; the Widget description gains Unicode café 雪; Wizard flags2 clears transient CONNECTED (0x40000000). All other source fields remain intact.

Each backend was generated by its own upstream dbconvert: `dbconvert BASE X < seed.flat > netrhost.db`. Native files were copied, then exported using `dbconvert COPIED_BASE x < COPIED_CHECKPOINT > export.flat`. Original native file hashes remained unchanged. Both exports are byte-identical; the seed differs only in attribute ordering. Unicode, attribute owner/flags metadata, embedded CRLF, timestamps, and terminator were checked explicitly.

Native payloads are individually gzip compressed with mtime zero. Decompress before passing them to the bridge; their original names, lengths and SHA256 digests are in provenance.json. Do not pass compressed files to dbconvert. MDBX lock files are omitted because they contain operational lock state.

QDBM requires `netrhost.db` plus all three `netrhost.gdbm.db`, `.dir`, `.pag`. MDBX requires `netrhost.db` plus `netrhost.gdbm.mdbx`. The supplied files are native upstream output, not mock layouts. Mail/folder databases are separate and were not fabricated; existing wmail/unload samples cover text mail separately.

The pinned upstream QDBM converter initially fails to compile/link: udb_ocache.c calls rhost_time without including externs.h. The reproduction script adds only that missing include in its private QDBM build copy. Original upstream checkout remains untouched and clean. Both final builds use normal warning settings; no warning suppression is required.

Reproduce with an existing clang, GNU make, and development libraries used by upstream defaults (OpenSSL, PCRE, crypt etc.):

```sh
python3 tools/rhost-fixtures/reproduce-fixtures.py /absolute/pinned/trunk /absolute/rhost-sample.flat /absolute/new-output
```

The script sets TMPDIR/TMP/TEMP to its output/scratch directory and makes no network calls. Build logs, exact selected preprocessor/library options, native hashes and converter binary hashes are recorded. Compiler diagnostics include upstream warnings; both converter links and all conversion invocations succeeded.

The recipe also writes a hash-bound `profile.json` beside each generated backend for the offline bridge. The dedicated `Rhost native export` CI workflow rebuilds both converters and exercises actual native round trips; ordinary runs explicitly skip those cases when exporter paths are unavailable.

The recipe copies only Git-tracked Server files, excluding ignored build artifacts from previously built upstream checkouts. Toolchain provenance uses short versions under `clang` and `GNU_make`; system and binary hashes describe each particular build. CI sets `RHOST_FIXTURE_ROOT` to the regenerated tree so inventory, parsed-field preservation, actual bridge round trips and isolated imports consume those newly generated fixtures. Ordinary tests default to the committed fixtures. Native database byte layouts and compiler binaries may differ across toolchains; regenerated files are validated against their own recorded hashes and the portable seed model.
